# Kubernetes Localization Helper

[English](README.md) | [日本語](README.ja.md) | [한국어](README.ko.md)

쿠버네티스 공식 문서([kubernetes/website](https://github.com/kubernetes/website))의 현지화(Localization/번역) 작업을 진행하는 기여자 및 관리자를 위해 설계된 경량 VS Code 확장 프로그램입니다. (외부 의존성 제로)

Markdown 문서의 경로가 `content/<lang>/` 하위에 있을 때 자동으로 활성화되며, **문맥 기반 용어집 호버**, **용어 밑줄 장식**, **스타일 및 번역 규칙 린터**를 제공합니다.

---

## 주요 기능

### 1. 🔍 대화형 용어집 호버 (Glossary Hover)
Markdown 문서 내의 기술 용어 및 구문(예: `Deployment`, `Control Plane`, `PersistentVolumeClaim`, `Pod`) 위에 마우스 커서를 올리면 다음 정보가 표시됩니다:
- **공식 번역 용어**: 표준 번역 용어 또는 명시적인 `🚫 Do Not Translate`(원문 유지) 안내.
- **문맥별 번역 규칙 (Contextual Rules)**: 쿠버네티스 리소스(`kind: Deployment`)인지, 일반 동작/동사인지, 일반 개념인지에 따른 권장 번역 기준 안내.
- **영한 병기 용어 정의**: 영문 및 번역 대상 언어로 작성된 간결한 정의.
- **번역 예문 (Usage Sample)**: 실제 문맥에서 사용되는 번역 예시.
- **공식 용어집 링크**: 쿠버네티스 공식 문서의 용어집 항목으로 바로 이동하는 링크.
- **다중 단어 및 별칭 자동 인식**: 여러 단어로 이루어진 구문(예: `persistent volume claim`)이나 복수형/대소문자 차이를 최장 일치 방식으로 자동 매칭.

### 2. ✨ 용어 밑줄 강조 장식 (Decorations)
- 등록된 용어집에 포함된 단어를 에디터 상에서 은은한 점선 밑줄(`underline dotted`)로 표시합니다.
- 번역 작업 중 어떤 단어에 공식 표준 번역이나 주의 사항이 있는지 한눈에 파악할 수 있습니다.
- 텍스트 편집 시 약 200ms 디바운스 처리되어 가볍고 빠르게 반응합니다.

### 3. 📏 스타일 및 번역 규칙 린터 (Style Linter)
공식 현지화 가이드에 맞춘 실시간 진단 기능을 제공합니다 (물결 밑줄 및 VS Code **문제(Problems)** 패널에 표시):

- **기계적 규칙 (Tier 1)**:
  - **구두점 검사**: 동아시아 문자 옆의 ASCII `,` 및 `.`을 감지하고 전각 기호 사용 권장.
  - **전각/반각 정규화**: 반각 카타카나, 전각 영숫자, 불필요한 전각 기호 감지.
  - **콜론 공백**: 문장 중간에 위치한 콜론 뒤에 반각 공백이 누락되었는지 확인.
  - **금지된 메타데이터**: 프론트매터(Front Matter) 내 금지된 필드(예: 번역본의 `reviewers:` 등) 감지.
  - **내부 링크 접두사**: 내부 문서 링크에 불필요하게 포함된 언어 접두사(예: `](/ja/docs/...)` → `](/docs/...)`) 감지.
  - **특정 번역 안티패턴**: 가이드에 명시된 주요 오역 패턴 감지.
  - **영문 제목 앵커 동기화 검사**: 해당 문서의 원문 영문 파일(`content/en/...`)을 대조하여, 원문에 명시적 앵커 ID(`{#anchor}`)가 있을 때 번역본에서 누락된 경우를 정확히 감지.

- **스크립트 경계 및 휴리스틱 규칙 (Tier 2)**:
  - **문자 간 공백 검사**: 영숫자와 한글/한자 사이의 불필요한 공백 검사.
  - **인라인 코드 공백**: 백틱 인라인 코드 스팬 주변의 공백 규칙 검사.
  - **괄호 및 마침표 순서**: `。)` 형태를 감지하고 `)。` 형태로 수정을 안내.
  - **문장 중간 줄바꿈 감지**: 마침표 등으로 끝나지 않은 연속된 본문 줄바꿈을 감지하여 의도치 않은 문장 중간 강제 줄바꿈 방지.

### 4. 🌐 다국어 지원 아키텍처 (Multi-Language)
- **경로 기반 자동 감지**: 파일 경로(`/content/<lang>/...`)에서 언어 코드(`ja`, `ko`, `pt-br`, `zh-cn`, `de`, `bn` 등)를 자동 인식.
- **독립적인 언어 모듈**: 용어집(`words/<lang>/`)과 린터 규칙(`linter/rules/<lang>/`)이 디렉토리별로 독립 관리됨.
- **손쉬운 확장성**: 한국어(`ko`) 및 일본어(`ja`)가 기본 내장되어 있으며, 새 언어도 JSON 파일 추가만으로 즉시 지원 가능.

## 지원 언어

| 언어 코드 | 언어명 | 용어집 (Glossary) | 스타일 린터 |
| :---: | :---: | :---: | :---: |
| `ja` | 일본어 (日本語) | ✅ 13개 카테고리 (600개 이상 용어) | ✅ Tier 1 + Tier 2 규칙 완비 |
| `ko` | 한국어 | ✅ 9개 카테고리 (500개 이상 용어) | 규칙 기여 접수 중 |
| `<lang>` | 기타 타깃 언어 | 🔌 `words/<lang>/` 추가 가능 | 🔌 `linter/rules/<lang>/` 추가 가능 |

## 동작 원리

1. **경로 기반 언어 감지**: `.../kubernetes-website/content/<lang>/...` 경로의 Markdown 파일을 열면 해당 언어 `<lang>`을 판별합니다.
2. **용어집 인덱싱**: `words/<lang>/` 경로의 모든 JSON 파일을 읽어 인메모리 접두사/단어 룩업 맵을 구성합니다.
3. **원본 문서 교차 검증**: 제목 앵커(`{#id}`) 등의 규칙을 검사할 때 워크스페이스 내 대응되는 `content/en/...` 원본 파일을 참조하여 원본에 실제로 앵커가 있는 경우에만 경고를 표시합니다 (진행 중인 번역본에서의 오경고 방지).
4. **순수 Node.js 엔진**: 텍스트 분석, 블록 경계 판정(프론트매터, 코드 블록, 인라인 코드, 테이블 행), 규칙 평가는 VS Code API에 의존하지 않는 순수 자바스크립트로 구현되어 매우 빠르며 단위 테스트가 용이합니다.

## 사용자 맞춤 설정 및 오버라이드 (Overrides)

확장 프로그램 코드를 직접 수정하지 않고도 홈 디렉토리에 개인 파일을 생성하여 용어와 규칙을 오버라이드하거나 추가할 수 있습니다:

- **개인 용어집**: `~/.md-japanese-word-list/<lang>/user-word-list.json`
- **개인 린터 규칙**: `~/.md-japanese-word-list/<lang>/user-lint-rules.json`

개인 설정 파일은 가장 마지막에 로드되어 `id`를 기준으로 병합되므로, 내장된 용어나 린터 규칙을 덮어쓰거나 나만의 규칙을 추가할 수 있습니다.

## 개발 및 테스트

이 프로젝트는 **외부 npm 런타임 의존성이 전혀 없으며**, Node.js 내장 테스트 러너를 사용합니다.

### 요구 사항
- Node.js >= 18.0.0
- VS Code >= 1.80.0

### 테스트 실행
```bash
npm test
```

용어 검색, 토크나이저, 최장 일치 알고리즘, 경계 분석 및 모든 린터 규칙을 검증하는 40개 이상의 단위 테스트가 실행됩니다.

### 로컬 디버깅 및 실행
1. 리포지토리 클론:
   ```bash
   git clone https://github.com/Greyeye/kube-localization-helper.git
   cd kube-localization-helper
   ```
2. VS Code로 열기:
   ```bash
   code .
   ```
3. `F5` 키를 누르거나 실행 및 디버그 탭에서 **Run Extension**을 선택합니다. 새 확장 프로그램 개발 호스트 창이 열립니다.
4. 해당 개발 호스트 창에서 `kubernetes/website` 리포지토리를 열고 `content/ko/` 또는 `content/ja/` 하위 파일을 열어 동작을 확인합니다.
