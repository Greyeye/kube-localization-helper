# Kubernetes Localization Helper

[English](README.md) | [日本語](README.ja.md) | [한국어](README.ko.md)

Kubernetes 公式ドキュメント（[kubernetes/website](https://github.com/kubernetes/website)）の翻訳・ローカライズ作業を行うコントリビューターおよびメンテナー向けに設計された、外部依存ゼロの軽量 VS Code 拡張機能です。

Markdown ファイルのパスが `content/<lang>/` 配下にある場合に自動で有効化され、**文脈に応じた用語集ホバー**、**用語の下線装飾**、**スタイル＆翻訳規約リンター**を提供します。

---

## 主な機能

### 1. 🔍 インタラクティブ用語集ホバー (Glossary Hover)
Markdown ドキュメント内の技術用語やフレーズ（例: `Deployment`, `Control Plane`, `PersistentVolumeClaim`, `Pod`）にカーソルを合わせると、以下が表示されます:
- **公式訳語**: 推奨される訳語、または明確な `🚫 Do Not Translate`（翻訳しない）指示。
- **文脈に応じた翻訳ルール (Contextual Rules)**: Kubernetes リソース名（`kind: Deployment`）か、動作・動詞か、一般的な概念かに応じた訳し分けのガイド。
- **日英対訳の用語定義**: 英語および翻訳先言語による簡潔な定義。
- **翻訳用例 (Sample)**: 実際の文脈での翻訳例。
- **公式用語集リンク**: Kubernetes 公式ドキュメントの用語集ページへの直接リンク。
- **複数語フレーズ・表記ゆれ対応**: 複数単語で構成されるフレーズ（例: `persistent volume claim`）や、複数形・大文字小文字の差異を自動認識して最長一致で検出。

### 2. ✨ 用語の下線ハイライト装飾 (Decorations)
- 登録済みの用語集に含まれる単語を、エディタ上で控えめなドット下線（`underline dotted`）でハイライト表示します。
- 翻訳作業中に、どの単語に公式訳や翻訳ルールが存在するかを一目で把握できます。
- テキスト編集時にも軽量に動作（約 200ms デバウンス処理）。

### 3. 📏 スタイル＆翻訳規約リンター (Style Linter)
公式ローカライゼーションガイド（`content/ja/docs/contribute/localization.md` など）に準拠したリアルタイム診断を提供します（波線下線および VS Code の「**問題**」パネルに表示）:

- **機械的ルール (Tier 1)**:
  - **句読点**: 日本語テキストと隣接する半角カンマ/ピリオド（`,` / `.`）を検出し、全角の「`、`」「`。`」を提案。
  - **全角・半角の正規化**: 半角カタカナ、全角英数字、不要な全角記号を検出。
  - **コロン前後のスペース**: 文中のコロンの後に半角スペースがあるかを確認。
  - **禁止メタデータ**: フロントマター内の禁止項目（日本語訳での `reviewers:` など）を検出。
  - **内部リンクのプレフィックス**: ドキュメント内部リンクに含まれる冗長な `/ja/` プレフィックス（`](/ja/docs/...)` → `](/docs/...)`）を検出。
  - **特有のアンチパターン**: ガイドで明示されている誤訳パターン（例: `cronのジョブ` → `cronジョブ`）を検出。
  - **英語見出しアンカーの同期確認**: 対応する英語原本（`content/en/...`）を参照し、原本に見出しアンカー（`{#anchor}`）が存在する場合に翻訳版での付け忘れを検出。

- **スクリプト境界・ヒューリスティックルール (Tier 2)**:
  - **和欧文間のスペース**: 英数字と日本語文字の間の不要な半角スペースを検出。
  - **インラインコード前後のスペース**: バッククォートによるインラインコード前後のスペースルール（日本語文字にはスペース不要、英単語にはスペース必須）を検証。
  - **括弧と句点の順序**: 「`。)`」を検出し、「`)。`」への修正を提案。
  - **文途中の改行検出**: 句点や読点（`。` / `、` / `:`）で終わらない連続した日本語散文行を検出し、意図しない途中改行を防止。

### 4. 🌐 多言語対応アーキテクチャ (Multi-Language)
- **パスベースの自動検出**: ファイルパス（`/content/<lang>/...`）から言語コード（`ja`, `ko`, `pt-br`, `zh-cn`, `de`, `bn` など）を自動認識。
- **独立した言語モジュール**: 用語集（`words/<lang>/`）とリンタールール（`linter/rules/<lang>/`）をディレクトリ単位で独立管理。
- **高い拡張性**: 日本語（`ja`）および韓国語（`ko`）を用意しており、他の言語も JSON ファイルを追加するだけで簡単にサポート可能。

## 対応言語

| 言語コード | 言語名 | 用語集 (Glossary) | スタイルリンター |
| :---: | :---: | :---: | :---: |
| `ja` | 日本語 | ✅ 13カテゴリ（600語以上） | ✅ Tier 1 + Tier 2 ルール完備 |
| `ko` | 韓国語 (한국어) | ✅ 9カテゴリ（500語以上） | ⏳ 近日対応予定（ルールコントリビューション歓迎） |
| `<lang>` | その他の言語 | 🔌 `words/<lang>/` を追加可能 | 🔌 `linter/rules/<lang>/` を追加可能 |

## 動作の仕組み

1. **パスベースの言語検出**: `.../kubernetes-website/content/<lang>/...` 以下の Markdown を開くと、言語 `<lang>` が特定されます。
2. **用語集のインデックス化**: `words/<lang>/` 配下の全 JSON ファイルを読み込み、高速な前方一致・単語マップをメモリ上に構築します。
3. **原本ドキュメントの相互参照**: 見出しアンカー（`{#id}`）の検証などでは、ワークスペース内の対応する `content/en/...` ファイルを自動特定して原本のアンカー有無を確認します（翻訳が遅れているドキュメントでも誤検知を防ぎます）。
4. **純粋な Node.js エンジン**: テキスト解析やブロック境界判定（フロントマター、コードブロック、インラインコード、テーブル行）、ルール評価は VS Code API に依存しない純粋関数として実装されているため、極めて高速に動作し単体テストも容易です。

## 個人設定とカスタマイズ (Overrides)

リポジトリ自体を変更することなく、ホームディレクトリに個人用ファイルを作成して用語やルールをオーバーライド・追加できます:

- **個人用用語集**: `~/.kube-localization-helper/<lang>/user-word-list.json`
- **個人用リンタールール**: `~/.kube-localization-helper/<lang>/user-lint-rules.json`

個人用設定は最後に読み込まれ、`id` に基づいてマージされるため、組み込みの用語やルールを上書きしたり、独自のルールを追加したりできます。

## 開発とテスト

本プロジェクトは**外部 npm 依存パッケージがゼロ**であり、Node.js 標準のテストランナーを使用しています。

### 必要環境
- Node.js >= 18.0.0
- VS Code >= 1.80.0

### テストの実行
```bash
npm test
```

用語集検索、トークナイザー、最長フレーズマッチ、境界解析、およびすべてのリンタールールを網羅する 40 以上の単体テストが実行されます。

### ローカルでのデバッグ起動
1. リポジトリをクローン:
   ```bash
   git clone https://github.com/Greyeye/kube-localization-helper.git
   cd kube-localization-helper
   ```
2. VS Code で開く:
   ```bash
   code .
   ```
3. `F5` キーを押す（または「実行とデバッグ」から **Run Extension** を選択）。新しい拡張機能開発ホストウィンドウが開きます。
4. そのウィンドウでクローン済みの `kubernetes/website` リポジトリを開き、`content/ja/` や `content/ko/` 配下のファイルを編集して動作を確認します。
